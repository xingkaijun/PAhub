登录、账户菜单与项目入口

  1. 打开平台并统一登录

    未登录时按提示进入 kjx-auth，用分配的个人账号登录，再返回原页面。首次登录或重置密码后按中央登录页要求改密；忘记密码联系账号管理员。登录成功不代表开通了所有应用，也不代表能看所有项目。

  2. 检查 Account 菜单

    顶栏显示姓名与角色。Account 中的 Change password 修改统一密码，My apps 查看已开通应用，Sign out 退出统一会话。退出会影响同一统一登录会话下的其他接入应用；不要把关闭标签页当作退出。

  3. 从大厅或切换器选项目

    kjx 没有项目密码提示。若项目不在列表，先让项目 admin／manager 检查 Team Setup，不要尝试用旧共享密码解锁。被移出成员后，项目会从列表移除，后续访问拒绝，已打开的实时连接关闭。

四种角色、成员范围与限制

项目成员是该项目 Default Leads、Default Assignees 与 Team Setup roster 中账号 ID 的并集；新项目的创建者自动加入。名单中手填的 manual- 人员只有姓名，不构成 kjx 成员。图纸上单独分配了负责人，也不等于加入 Team Setup。旧的全局 roster 无法自动判断项目归属，需要管理员把人加入正确项目。

角色项目范围与常见操作不能做的事
admin 管理员看到全部项目；管理项目团队及 Config、图纸与 PCF、代勾 Tracker、导入导出；可用 Local Backup、Fix Deadline 和管理后台（实际入口 /api/admin）。破坏性操作前仍须确认与备份；当前没有正式的项目删除入口。
manager 主管仅进入本人为成员的项目；可创建项目、用 Config 管理 Team Setup、Default Leads／Default Assignees、常规审图周期、节假日、报告名称等项目配置；改图纸负责人、状态、备注，编辑他人 PCF、指定提出人、导出和导回船厂回复、代勾 Tracker。不能进入非成员项目；不能用 Local Backup、Fix Deadline、全局设置、管理后台（/api/admin）、图纸作废或 PCF 历史恢复等仍为 admin 专属的动作。
reviewer 审图人成员项目内查看 Inventory、Comments、Activity、Log 和报表；新增 PCF 意见／单条新轮，编辑本人轮次 Owner 内容和行高；勾选自己的 Tracker 栏。Inventory 只读，无 Config；不能改他人轮次、Reply 或提出人，不能替别人勾选。整条意见的状态／页码／标签仅在全部轮次均为本人时可改。
viewer 查看者成员项目内查看列表、PCF、Comments、Activity、Log 和可用报表。无 Config；不能写 PCF 或勾 Tracker，也不能编辑图纸。

“本人意见”按轮次保存的账号 ID 判断，不是按姓名。缺账号 ID 的旧轮次不会被认作本人；请 manager／admin 处理。admin／manager 的 Owner 下拉显示已存提出人，可选择服务器校验的候选；目录不可用时只能选择本人，原作者仍显示为只读姓名。

Inventory：相同列样式、只读控件与 Assignees

reviewer／viewer 的 VER、DISCIPLINE、STATUS、TOTAL CMT、OPEN CMT 等列与常规主表使用统一小字号和状态徽标，但不能点击进入编辑。ASSIGNEES 都用头像圆点表示，鼠标停留查看姓名；可编辑角色点击展开勾选，只有查看权限时不打开勾选列表。

头像、姓名和下拉勾选来自同一解析结果：优先账号 ID，唯一姓名兼容旧数据；同一人的 ID／姓名不重复显示。无法解析的 UUID 显示 Unknown reviewer，请项目管理人员重新分配正确账号，不要把 UUID 当姓名或手工猜测重名身份。

Tracker：本人勾选与代勾审计

reviewer 只能勾／取消自己实际被分配的账号那一栏。无权栏位置灰并提示 Only this reviewer or a project manager can change this mark。项目成员 manager 和 admin 可替任一已分配人员勾／取消；服务端同时记录实际操作人 Actor 与被操作人员 subjectId。viewer 不能勾选。旧负责人若只存姓名，须先改为正确 kjx 账号 ID 才能本人勾选。

Ready 表示各负责人都完成，不等于已发出。manager／admin 的 Send All 按确认流程更新状态并打包；APR 为手动标记，不从 PCF 自动继承。船厂导出本身不改变状态，导回回复仅将 Waiting Reply 转回 Reviewing，其他状态不自动改变。

Config、Team Setup 和专业默认人员

  1. 进入成员项目的 Config 或 Team Setup

    manager／admin 可管理本项目人员。Config 可改常规项目设置；reviewer／viewer 看不到可编辑的 Config。Local Backup、Fix Deadline 及后台权限没有因此开放给 manager。

  2. 从目录选账号

    Team Setup 和 Default Leads 从 kjx 目录选择人员；目录列出已开通 PAhub 的 admin、manager、reviewer，按专业映射筛选。浏览器只请求 PAhub，不直接连接目录。目录不可用时显示 “Directory unavailable, enter the name manually.”；手填是本项目姓名，不会赋予统一账号成员权限。

  3. 设 Default Leads

    Config 的 Default Leads 每专业一条紧凑行、一个下拉，显示当前 lead 姓名；无 lead 时显示 Select … lead。整列可以滚动，目录不可用仍保留当前姓名，不是“没选上”。

  4. 设 Default Assignees

    Team Setup 按专业分组，使用 Select … reviewer 选人，并在下方名单切换默认负责人。这里可多选，不是 Default Leads 的单选下拉。Apply & Reset All 会将专业默认负责人应用到图纸，请确认影响后执行。

  5. 删除项目 reviewer

    使用 Remove member／Roster 删除按钮并确认。服务端事务清理本项目图纸负责人、Default Leads、Default Assignees 和 roster 引用并写审计；其他项目引用保留，Tracker 历史不删除。不能通过此入口删除自己的成员关系以免误锁出项目；失败会显示明确错误，不要把按钮点击当作保存成功。

自动保存、权限拒绝和 Daily Log

常规项目脏数据每 15 分钟自动保存一次，状态栏显示下次自动保存时间，Save Now 立即保存；保存不遮挡或打断编辑。隐藏页面/pagehide 尽力保存，保留关闭提醒与切换项目前先保存的阻止策略。失败以 3–60 秒退避独立重试；回读失败标“待确认”并保留待同步。本地存储满/禁用会告警，请保持页面打开并 Save Now。kjx 托管 PCF 同为 15 分钟，保留手动保存、离开提醒及 IndexedDB 恢复。Data Management 在 kjx 不再显示 Save to Cloud、Cloud Fetch、Local Restore。不要把输入完成或“正在自动保存”当作服务器已确认；查看待同步提示、成功结果或重新读取。

无权限字段从一开始只读，不应产生本地修改。如果权限在编辑后变化、服务端返回 403，项目乐观修改会回滚到服务器值或编辑前快照、清除待同步标记，并提示无权限；这次未获准的修改不会保留在浏览器待提交队列。网络故障和 409 并发冲突另按页面提示处理，不等同于权限拒绝。

kjx Daily Log 只保留 Server，默认 Raw entries；Refresh 手动刷新，本项目 SSE 变更节流刷新；Load more 每页 500 条，不再 2000 条截断（导出仅含已加载记录）。Merged consecutive 只合并同日同一人同一图纸的相邻意见事件，中间其他人/图纸/状态修改会断开，未知操作人不合并。Server 查看实际落库记录；Actor 可选 All 或操作人，Copy／CSV／PDF 包含 Actor。旧日志、legacy 或没有请求用户的系统记录显示 “—”。导入船厂回复记 Builder Reply 行，计数没变也有记录。Tracker 勾选显示 In progress，Failed — Retry 保留原意图；回执丢失时以回读结果为准。

Data Management、备份与项目删除

  • Local Backup：仅 admin，下载当前单项目离线备份（包括项目数据与 Tracker）；不是完整服务器灾备，也不包含全部 PCF 文件、历史和交换基线。
  • Fix Deadline：仅 admin，确认后重算 Reviewing 图纸期限并走自动保存。提示正在保存后仍要等待成功；不需要再点已移除的 Save to Cloud。
  • 全库 JSON：admin 可在管理后台（常称“/admin 后台”，PAhub 实际入口为 /api/admin）导出 JSON，包含该后台导出支持的全部项目数据；这不是 SQLite／PCF 全数据目录快照。完整灾备与恢复由运维按备份流程处理。
  • Local Restore：kjx 无此本地恢复入口；不要用旧截图里的按钮恢复线上项目。需要恢复时联系管理员核对备份和影响。
  • 删除项目：当前没有正式的用户项目删除功能，请联系管理员，不要将删除 reviewer 或删除图纸误认为删除项目。

按角色的常见操作

  • reviewer：选成员项目 → 核对 Assignees 姓名 → 进入 PCF 新建本人意见／编辑本人 Owner → 检查保存结果 → Tracker 勾自己的完成栏。
  • manager：选成员项目 → Config／Team Setup 调整人员和审图设置 → Inventory 改负责人／状态 → 处理意见、船厂往来及必要的 Tracker 代勾。
  • admin：处理全项目成员授权、异常身份快照、Local Backup／Fix Deadline、后台导出和恢复请求。
  • viewer：浏览授权项目和报表；需要修改请找项目负责人，不要尝试通过旧入口写入。

看不到项目：联系 admin／项目 manager 核对三处 Team Setup 来源；成员被移除后再次访问拒绝是正常保护。Unknown reviewer：请补人员快照或重新分配 ID。修改被回滚：先核对角色与成员权限，恢复权限后再重新输入。

平台概览和整体工作流

一张图纸从进平台到批准，会经过四个状态：Pending（待审）、Reviewing（审图中）、Waiting Reply（等船厂回复）、Approved（已批准）。每张图纸有一份在线 PCF，意见、回复、轮次都记在里面，平台数据库是唯一的数据来源。

  1. 建项目

    管理员在项目选择页点 Create Workspace，输入船号或项目名，例如 PG-VLEC-H2684。

  2. 导入图纸、分配人员

    主表点 Bulk Load 粘贴图纸清单；Config 里设好每个专业的负责人，再用 Team Setup 一次性分配审图人。

  3. 开始审图（A 轮）

    把图纸状态改成 Reviewing，系统按 A 轮周期（默认 14 个工作日）自动算出截止日。

  4. 写意见

    审图人员点图纸标题打开在线 PCF 写意见、贴附图；写完在 Tracker 里勾上自己的名字，全部勾完图纸就显示 Ready。

  5. 发给船厂

    管理员在 Tracker 点 Send All：点了 APR 的图纸转 Approved，其余转 Waiting Reply，并下载一个给船厂的压缩包，发邮件给船厂。

  6. 船厂回复

    船厂用浏览器打开 HTML，只在本轮未关闭的意见下填回复，点 Save copy to return 另存后发回。

  7. 导回合并

    管理员在主表用 Import Builder Replies 批量导回，预览无冲突就确认合并，图纸从 Waiting Reply 自动回到 Reviewing，轮次加一（A→B）；其他状态的图纸导回后状态不变。每次导回都会在 Log 的 Server 视图留一条 Builder Reply 记录。

  8. 下一轮或关闭

    审图人员看回复，关闭已解决的意见，未解决的进入下一轮；全部关闭后改成 Approved。

状态变化系统自动做的事
任何状态 → Reviewing按周期算截止日，只算工作日，跳过周末和节假日，按北京时间算
Waiting Reply → Reviewing轮次加一：A→B→…→Z→AA；PCF 里同时开出新一轮
离开 Reviewing清掉截止日
周期设置A 轮默认 14 个工作日，之后每轮默认 7 个，在 Config 里改

  • 管理员登录：点右上角的 Reviewer 按钮，输入管理员密码点 Sign in。密码来自服务器环境变量 ADMIN_PASSWORD。
  • 有效期：登录 12 小时有效；连续输错 5 次要等 10 分钟才能再试。
  • 退出：再点一下 Administrator 按钮就退出。
  • 没设 ADMIN_PASSWORD 时：所有人都算管理员，不用登录。
  • 项目密码：项目可另设访问密码，与管理员密码不同。受保护项目须先在大厅加载页解锁；管理员会话和带有效 API_TOKEN 的请求免输项目密码。项目解锁不会授予管理员写权限。下面表格中的项目操作均以已解锁为前提。

项目选择页和顶栏

项目选择页（Project Access Hall）

打开平台默认到蓝图大厅。每个项目一张卡片，显示项目缩写、Completed 或 Active、进度百分比、图纸数（Assets）和最后更新日期；受保护项目带小锁。刷新到受保护的上次项目或项目 URL 时，若没有有效解锁 cookie，会在大厅对该项目自动打开同一加载页密码流程。

  • 打开项目：点卡片，卡片照常展开为全屏加载页（PG 标志、项目名）。有密码且尚未解锁时，输入框直接显示在这张加载页上并自动聚焦，按回车或 “Unlock” 提交（输入框标签是 Project password），不再弹出浏览器原生 prompt。
  • 密码错误或取消：错误在原位显示，可重试；同一来源对同一项目 10 分钟内失败 5 次后临时限速。点 “Cancel” 或按 Esc，加载页淡出回大厅，卡片恢复可用。密码正确后继续加载，再照常淡出进入 Inventory；无密码项目流程不变。
  • 解锁有效期：服务端签发该项目专属 HMAC 签名 cookie，HttpOnly、SameSite=Strict、12 小时有效；Secure 按实际 HTTPS 或 X-Forwarded-Proto 首项判断，与管理员会话一致。刷新、自动同步、drawings、PCF 页面/API、SSE、活动、日志、报表和导出都凭 cookie 访问，不必反复传密码头。未解锁的项目接口返回 401 PASSWORD_REQUIRED，PCF 页面提示返回大厅。修改或清除密码会更新版本，使旧解锁 cookie 立即失效。
  • 刷新列表：右上角的刷新按钮。
  • 新建项目（管理员）：最后一张卡片 Create Workspace，按提示输入船号或项目名，例如 PG-VLEC-H2684。
  • 离线模式：底部 Skip / Enter Offline Mode (Local Cache)，打开浏览器里缓存的本地数据。

Send All 一键发送 看代码推断

  1. 把要发的图纸审完

    所有审图人都在 Tracker 勾了完成，图纸进入 Ready Drawings。要直接批准的，先点 APR。

  2. 点 Send All

    弹出确认：“Update the status of N Ready drawing(s): • a → Approved • w → Waiting Reply. After sending, a builder PCF archive for p drawing(s) downloads automatically (x without a PCF will be skipped). Continue?”。只有点了 APR 的转 Approved，其余全部转 Waiting Reply；压缩包里包括这些 Ready 图纸中所有有 PCF 的。

  3. 等它跑完

    按钮依次显示 Sending...、Verifying...、Packing...：先保存状态、清掉这些图纸的勾选和 APR，再从服务器回读核对，最后下载一个压缩包，里面是每张图纸的船厂版 HTML。

  4. 发邮件

    把压缩包发给船厂。压缩包没保存好，点顶部的 Download Again 重新生成。

  • “Statuses were updated locally, but saving to the server failed. Click Save Now to retry.”：状态只改在本地，没存到服务器。点右下角 Unsaved Changes 卡片上的 Save Now 重试（失败后按 3–60 秒退避重试；正常自动保存仍是 15 分钟）。
  • “Saved, but the server write check failed …”：点 Refresh 核对状态，需要时再点 Save Now。
  • “Statuses were sent, but the archive download failed …”：状态已经改了，点 Download Again 再下一次，或点 Dismiss 关掉提示。
  • 没有 PCF 的图纸：状态照改，但不进压缩包。

船厂回复导回记录（Builder Reply）

批量导回（主表 Import Builder Replies）和单个文件导回（在线 PCF 的 EXPORT ▾ → Import Builder Reply）每成功合并一个文件，服务器就记一条 Builder Reply 日志。船厂回复不改意见总数和未关闭数，所以以前在 Log 里看不出来，现在切到 Server 就能看到，例如：

  • Builder replies imported: 2 replies (Round B) · status unchanged (Reviewing)
  • Builder replies imported: 1 reply (Round A) · status Waiting Reply -> Reviewing
  • 内容：导回的回复条数、回复的是哪一轮、状态结果；Note 列写来源（Builder reply import (bulk) 或 Builder reply import (PCF)）。

写意见

  1. 加一条意见

    点 + Add comment，或在输入框外按 N。每条意见有固定 ID，显示的编号在删除后会重排。

  2. 填内容

    每轮一行，左边船东意见、右边船厂回复。姓名在意见标题里改，新轮次会沿用上次填的名字。

  3. 打属性标签

    卡片上的 SPEC、highlight、site verify、Cost Affect 点一下开关，工具栏可以按这些属性筛选。

  4. 关闭或重开

    把状态胶囊左右拖动切换 Open/Closed，单击没有反应；键盘用左右方向键。关闭的意见是只读的，要改先重开。

  5. 开新一轮

    单条意见点卡片上的 + Round；工具栏的 + Round to open 给所有未关闭意见一起加一轮，包括其他页的。从船厂导回时平台也会自动开新轮。

  6. 删除

    卡片上的 Delete。只有没有回复文字和回复图片的轮次能单独删；确认后永久删除。

HISTORY 和船厂的往来记录

每次 Export to Builder 都会在这里留一行：导出时间、轮次、基线版本（Base rev）、状态（如 Awaiting reply），以及 Download（重新下载当时发出的文件）和 Void。每次导出都有自己的基线，导回时按这个基线合并。

  • Void 作废导出（管理员，访客看到的按钮是灰的）：发错文件或想让某份文件失效时用。作废后这份文件的回复不能再导回，但仍然可以下载。
  • 服务器历史快照 看代码推断：每次保存服务器都留快照，按规则保留：最近 50 份全留，30 天内每天留最后一份，30–180 天每周一份，更早的每月一份。页面上没有入口，只能通过接口查看（GET /pcf/项目/图纸/history）和恢复（POST /pcf/项目/图纸/history/序号/restore）。

    点黄色提示条旁边的绿色按钮 Save copy to return（和 Save options → Save as 一样）。Chrome 和 Edge 会弹出保存对话框，其他浏览器直接下载。

    把另存的 HTML（多张可以打成 ZIP）邮件发回船东。不要用别的工具改文件内容，文件名可以改，匹配靠的是文件里的编号。

船东：批量导回 Import Builder Replies（管理员）

  1. 打开导回窗口

    主表点 Import Builder Replies（手机在 More 里），或直接把文件拖到主表上。

  2. 放入文件

    拖入或选择 ZIP 或多个 .html。一次最多 50 个文件、共 50 MB。

  3. 点 Preview replies

    逐个文件列出 File、Drawing、Round、New replies、Auto、Conflicts、Result、PAPC status。匹配靠的是文件里嵌的导出编号，不看文件名。

  4. 点 Apply all clean

    导回所有没有冲突的文件。写入前会再预览一次，这期间有人改了的会变成 Conflict。图纸是 Waiting Reply 的自动转回 Reviewing 并进入下一轮；其他状态不动；不会自动变 Approved。每个导回成功的文件在 Log 里记一条 Builder Reply。

  5. 处理冲突

    Conflict 行点 Resolve…，会打开那张图纸的 PCF 逐条处理；不想处理点 Skip。没处理的冲突、跳过的、船东内容被改的，下次打开窗口还会列出来。点 New import 重新开始。

提示条和多人编辑冲突

黄色：保存冲突

主表和项目设置保存时只发改过的字段，并带上版本号和改之前的值。

  • 改的是不同字段：比如一个人改标题、另一个改专业，两边都保留，不提示。
  • 改的是同一字段：后保存的人这一批一条都不写入，页面顶部出现黄色提示条，例如 “Save conflict: DW-A-001 (Version) changed by someone else first. Nothing was saved this time. …”。
  • 冲突后的处理：冲突的字段换成服务器上的最新值，你其他没冲突的改动保留，下次自动保存时再发。看一下换回来的值，需要的话重新改。
  • 项目设置冲突：提示写 “Save conflict: project settings (Round A Cycle) changed by someone else first …”；专业负责人按专业分别比较。
  • 旧页面不受保护：平台更新后，还开着旧页面没刷新的人保存时仍会直接覆盖。更新后让大家刷新一下。

红色：项目不存在

  • 打开时服务器上没有这个项目：顶部红色提示 “Project "…" does not exist on the server…”，页面停在项目选择页，不会打开本地那份旧数据。
  • 正开着的项目被别人删了：提示写 “no longer exists”。
  • 例外：刚用 Create Workspace 建好、还没第一次保存到服务器的项目，照常打开。

  • 里面有什么：数据库 papc.db；每张图纸的 PCF pcf/项目ID/图纸ID.json；历史快照 .history/图纸ID/；按哈希存的图片；船厂回传文件 imports/；导出签名密钥 .pcf-export-key。

启动时自动迁移

Hub 启动、开始监听之前，会检查有没有旧的 HTML 格式或混合存储的 PCF。有的话：

  • 先备份：把 PCF 目录和数据库备份到 数据目录/backups/before-pcf-json-时间-编号/。
  • 再转换：转成 JSON，原来的 HTML 目录改名保留为 pcf-html-backup-*。
  • 失败时：日志写明原因，继续用旧格式读写；修好原因后重启会再试。
  • 只做一次：成功后不再重复。

自动迁移只管 HTML 转 JSON，不管图片。图片拆分要自己跑下面的 hub:migrate-pcf-images。

项目密码：升级与自动迁移

  1. 停服、备份并配置管理员密码

    升级前停止 Hub，备份整个数据目录。对外部署必须设置 ADMIN_PASSWORD；否则所有访客都按本地开发模式视为管理员，免输项目密码。拉代码后重新 npm run hub:build 再启动，推到 main 不会自动部署。

  2. 启动先备份、再迁移

    监听之前，SQLite VACUUM INTO 创建含已提交 WAL 内容的一致全库备份：PAHUB_DATA_DIR/backups/before-project-password-<时间戳>-<随机编号>.db。随后事务中使用 node:crypto 的 scrypt 和随机盐，把旧明文迁到独立 project_passwords 哈希表，并删除 project_settings.password。迁移幂等，无明文则不再备份，无需手工重设原密码。数据库和备份目录须可写；备份或迁移失败会拒绝启动，不会继续明文服务。

  3. 保护旧明文备份

    迁移备份仍包含旧明文密码，要限制文件权限、离线保管，Windows 上核对 ACL。不要放进仓库或经网页下载。API、项目详情/列表、JSON 和后台导出均不返回密码或哈希。

  4. 需要回滚时

    先停服、另存当前数据库，再将迁移前备份恢复到 PAPC_DB_PATH；移走当前库的 -wal / -shm 文件，并按完整备份恢复相关数据，再启动匹配旧版本。不要让旧版本直接运行在迁移后的库上。重启后需重新建立项目解锁会话。

图片迁移 hub:migrate-pcf-images

  1. 停服并备份

    停掉 Hub，把整个数据目录拷一份。

  2. 试跑

    npm run hub:migrate-pcf-images -- --data-dir <数据目录> --dry-run

    只统计，不写入。

  3. 实跑

    npm run hub:migrate-pcf-images -- --data-dir <数据目录> --hub-stopped

  4. 启动 Hub

    确认没问题后，备份目录可以删。注意：之后每张图纸下次保存时，会按新的保留规则删掉多余的旧快照。

小技巧和常见问题

小技巧

  • 从意见直接跳进 PCF：Comments 里点一行，打开对应 PCF 并高亮那条意见。
  • 批量改状态：命令栏 @R 001,002,003，比一行行下拉快。
  • 批量换人：@张三 add: 001 002 把一个人加到多张图纸。
  • 催办：Tracker 点 Urge List 只看过期的，再 Export CSV 发给大家。
  • 标记要事：给图纸加 #urgent 或 #hold 备注，主表 ID 前出现红点或琥珀点，搜索 show:#urgent 一下都能找到。
  • 批量导回最省事：把船厂发回的 ZIP 直接拖到主表上。
  • PCF 快捷键：输入框外按 N 加意见；Ctrl+B/I/U 改字形；状态胶囊左右拖开关；双击行的下边恢复行高。
  • PCF 里批量开新轮：+ Round to open 一次给所有未关闭意见加一轮。
  • 意见太多滚不动：PCF 每页设 25 条，用 ☰ Index 跨页跳转。
  • 发错给船厂的文件：在 HISTORY 里 Void 掉，这份的回复就导不回来了。

常见问题

  • 按钮是灰的、提示 “Administrator permission required”：右上角登录管理员。
  • 主表里版本和意见数改不了：有 PCF 的图纸这两项由 PCF 管，到 PCF 里改。
  • 轮次怎么改：不能手工改。Waiting Reply 转回 Reviewing 时自动加一，导回船厂回复时会自动转。
  • Comments 里看不到最新意见：点 Refresh register。
  • Activity 报告打印不了：先点 Refresh comments。
  • 船厂说文件存不了：让他们点绿色的 Save copy to return，用 Chrome 或 Edge；其他浏览器会直接下载到下载文件夹。
  • 导回时显示 Unable to match：文件不是这个项目发出的，或压缩包损坏、加了密。
  • 导回时显示 Owner changed：船厂改了船东意见，这部分会被忽略，回复照常导入。
