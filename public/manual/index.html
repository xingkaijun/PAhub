统一登录（kjx）

本章适用于切换到统一登录后的平台；下文原有的访客／管理员操作说明和截图适用于尚未切换的 legacy 模式。统一登录的界面与权限按以下说明为准。

登录和退出

  1. 登录

    打开 PAhub，按提示使用管理员分配的统一账号登录；登录后回到原来的页面。同一个账号可用于已开通的 PAhub 和 nbins，不代表自动开通两个系统。

  2. 修改密码

    首次登录或管理员重置密码后，按提示先修改密码；平时可在用户菜单点 Change password。忘记密码请联系管理员重置。

  3. 退出

    在用户菜单点 Sign out。统一会话会在所有接入该登录的系统同时退出；空闲 12 小时或会话最长 7 天后需要重新登录。

四种角色能做什么

角色可以做什么主要限制
viewer（查看者）查看项目、列表、报表、Daily Log 和 PCF。不能写入或修改意见。
reviewer（审图人）新增意见和单条新轮；修改自己轮次的船东意见、意见状态、标签等属性及行高。不能改他人意见、船厂回复或提出人，也不能删除或恢复记录；不能批量给所有意见开新轮。
manager（主管）包括审图人的工作；可改他人意见和船厂回复，修改图纸状态、负责人和备注，执行批量导入、批量命令及船厂文件导出和回复导回；可修改 PCF 文档及显示设置。Team Setup、项目 Settings、创建项目、作废、历史恢复及管理控制台等仅 admin 可操作。
admin（管理员）具有上述全部能力，还可管理 Team Setup、项目设置和项目、作废、历史恢复及管理控制台。进行替换、删除等操作前请先确认影响并备份。

“只能改自己的意见”是什么意思？

按每个轮次判断：系统记录该轮次的提出人账号 ID，而不是只看显示的名字。新建意见或轮次时，服务端会忽略页面传来的身份并自动记录当前登录人。reviewer 只能编辑属于自己的轮次的 Owner 内容和行高；整条意见的状态、页码或标签只有在所有轮次都属于自己时才能修改。reviewer 不能编辑 Reply、更改提出人或删除／恢复记录。旧轮次如果没有记录账号 ID，即使显示名字相同也不能认作自己的；请找 manager 或 admin 处理。admin／manager 指定其他团队成员的提出人下拉尚待 T6 上线。【待 T6 合并后核对】

为什么登录后还要输入项目密码？

统一账号证明你是谁；项目密码是受保护项目的第二道访问门槛。除 admin 可直接进入外，其他角色仍须输入该项目的密码解锁；解锁不会提高账号角色权限。没有项目密码请联系项目管理员。

日常使用与常见问题

  • 没有 PAhub 访问权限：请管理员检查账号是否启用、是否已开通 PAhub 角色；登录成功不等于有所有应用的权限。
  • 按钮不可用或操作被拒绝：先确认当前角色、项目是否解锁，以及意见轮次是否属于自己；仍需操作时联系 manager 或 admin。
  • 查看谁做了修改：服务端已记录操作人；Daily Log 的 Actor 列和按人筛选将在 T6 提供。旧记录和无登录人的后台操作没有操作人。【待 T6 合并后核对】
  • 分配审图人：当前仍使用项目已有名单；Team Setup 从统一目录选择人员及目录不可用时手填将在 T6 提供。【待 T6 合并后核对】
  • 登录服务暂不可用或图片显示异常：稍后重试；会话过期时重新登录并刷新页面。持续失败请联系管理员。

平台概览和整体工作流

一张图纸从进平台到批准，会经过四个状态：Pending（待审）、Reviewing（审图中）、Waiting Reply（等船厂回复）、Approved（已批准）。每张图纸有一份在线 PCF，意见、回复、轮次都记在里面，平台数据库是唯一的数据来源。

  1. 建项目

    管理员在项目选择页点 Create Workspace，输入船号或项目名，例如 PG-VLEC-H2684。

  2. 导入图纸、分配人员

    主表点 Bulk Load 粘贴图纸清单；Config 里设好每个专业的负责人，再用 Team Setup 一次性分配审图人。

  3. 开始审图（A 轮）

    把图纸状态改成 Reviewing，系统按 A 轮周期（默认 14 个工作日）自动算出截止日。

  4. 写意见

    审图人员点图纸标题打开在线 PCF 写意见、贴附图；写完在 Tracker 里勾上自己的名字，全部勾完图纸就显示 Ready。

  5. 发给船厂

    管理员在 Tracker 点 Send All：点了 APR 的图纸转 Approved，其余转 Waiting Reply，并下载一个给船厂的压缩包，发邮件给船厂。

  6. 船厂回复

    船厂用浏览器打开 HTML，只在本轮未关闭的意见下填回复，点 Save copy to return 另存后发回。

  7. 导回合并

    管理员在主表用 Import Builder Replies 批量导回，预览无冲突就确认合并，图纸从 Waiting Reply 自动回到 Reviewing，轮次加一（A→B）；其他状态的图纸导回后状态不变。每次导回都会在 Log 的 Server 视图留一条 Builder Reply 记录。

  8. 下一轮或关闭

    审图人员看回复，关闭已解决的意见，未解决的进入下一轮；全部关闭后改成 Approved。

状态变化系统自动做的事
任何状态 → Reviewing按周期算截止日，只算工作日，跳过周末和节假日，按北京时间算
Waiting Reply → Reviewing轮次加一：A→B→…→Z→AA；PCF 里同时开出新一轮
离开 Reviewing清掉截止日
周期设置A 轮默认 14 个工作日，之后每轮默认 7 个，在 Config 里改

权限

本节仅适用于 legacy 模式；统一登录后的四种角色及项目密码规则见统一登录（kjx）。

平台只有两种身份：访客（界面上叫 Reviewer）和管理员（Administrator），另外船厂拿到的是离线 HTML，不进平台。

能做什么访客管理员船厂（离线文件）
看所有页面（含 Activity、Log、Tracker、Comments、Guide）能能不进平台
看 Config 页不能，标签带锁能—
打开在线 PCF、写意见、贴图、保存能能—
在 Tracker 勾选自己完成能能—
导出 Excel、打印版 Excel、导出给船厂（PCF 内）能能—
主表编辑和保存（标题、专业、人员、版本等）不能能—
改图纸状态（含命令栏 @R/@W/@A）不能能—
命令栏、Bulk Load、Team Setup、删图纸不能能—
导入船厂回复（批量）、导入 JSON、Send All不能能—
新建项目、改项目设置不能能—
在本轮未关闭的意见下填回复、附图——能
改船东意见、旧轮次内容——不能，只读；改了导回时也会被忽略
  • 管理员登录：点右上角的 Reviewer 按钮，输入管理员密码点 Sign in。密码来自服务器环境变量 ADMIN_PASSWORD。
  • 有效期：登录 12 小时有效；连续输错 5 次要等 10 分钟才能再试。
  • 退出：再点一下 Administrator 按钮就退出。
  • 没设 ADMIN_PASSWORD 时：所有人都算管理员，不用登录。
  • 项目密码：项目可另设访问密码，与管理员密码不同。受保护项目须先在大厅加载页解锁；管理员会话和带有效 API_TOKEN 的请求免输项目密码。项目解锁不会授予管理员写权限。下面表格中的项目操作均以已解锁为前提。

项目选择页和顶栏

项目选择页（Project Access Hall）

打开平台默认到蓝图大厅。每个项目一张卡片，显示项目缩写、Completed 或 Active、进度百分比、图纸数（Assets）和最后更新日期；受保护项目带小锁。刷新到受保护的上次项目或项目 URL 时，若没有有效解锁 cookie，会在大厅对该项目自动打开同一加载页密码流程。

  • 打开项目：点卡片，卡片照常展开为全屏加载页（PG 标志、项目名）。有密码且尚未解锁时，输入框直接显示在这张加载页上并自动聚焦，按回车或 “Unlock” 提交（输入框标签是 Project password），不再弹出浏览器原生 prompt。
  • 密码错误或取消：错误在原位显示，可重试；同一来源对同一项目 10 分钟内失败 5 次后临时限速。点 “Cancel” 或按 Esc，加载页淡出回大厅，卡片恢复可用。密码正确后继续加载，再照常淡出进入 Inventory；无密码项目流程不变。
  • 解锁有效期：服务端签发该项目专属 HMAC 签名 cookie，HttpOnly、SameSite=Strict、12 小时有效；Secure 按实际 HTTPS 或 X-Forwarded-Proto 首项判断，与管理员会话一致。刷新、自动同步、drawings、PCF 页面/API、SSE、活动、日志、报表和导出都凭 cookie 访问，不必反复传密码头。未解锁的项目接口返回 401 PASSWORD_REQUIRED，PCF 页面提示返回大厅。修改或清除密码会更新版本，使旧解锁 cookie 立即失效。
  • 刷新列表：右上角的刷新按钮。
  • 新建项目（管理员）：最后一张卡片 Create Workspace，按提示输入船号或项目名，例如 PG-VLEC-H2684。
  • 离线模式：底部 Skip / Enter Offline Mode (Local Cache)，打开浏览器里缓存的本地数据。

Print List 打印清单

打印的是当前筛选和搜索下的全部图纸，不分页。页眉有 Logo、Plan Approval Status、项目名、生成日期和筛选条件，列为 ID、Code、Ver、Rd、Discipline、Title、Deadline、Days、Assignees、Status、Cmt、Opn。

Bulk Load 批量导入图纸（管理员）

  1. 点 Bulk Load

    弹出 Fleet Bulk Entry 窗口。

  2. 粘贴清单

    每行一张图纸，格式 ID, 图号, 专业, 标题，例如 001, PG-VLEC-H2684-01, Hull, General Arrangement Plan。用英文逗号、中文逗号或 Tab 分隔都行，直接从 Excel 复制四列也可以。

  3. 点 Execute Import

    新图纸状态是 Pending、版本 0、没有审图人，接着自动保存。点 Discard 放弃。

  • 标题里可以有逗号：第三个逗号后面的内容全部算标题；也可以用带引号的 CSV 写法，或者直接从 Excel 复制四列。
  • 不去重：重复粘贴会重复添加；不足四段的行会跳过，并弹提示列出来。

Team Setup 按专业分配审图人（管理员）

  1. 点 Team Setup

    按图纸里出现过的专业逐个列出；打开时会自动把 Config 里设的专业负责人加进去。

  2. 点人名选人

    选中的人名变成靛蓝色，右边显示 “N assigned”。只关窗口点 Close。

  3. 点 Apply & Reset All

    确认后，每张图纸的审图人都会被重置成它所属专业的默认人选；没设人选的专业会被清空。

命令栏语法（管理员）

主表上方的黑色终端框，输入后按 Enter。访客看到的是 “Terminal commands require administrator sign-in”，不能用。

输入效果
show:hull 或 ls:hull按关键字筛选，和搜索框一样；冒号用中文全角也行
reset、clr、clear清空筛选
@R 001,002批量改成 Reviewing；@W 改成 Waiting Reply，@A 改成 Approved。编号用逗号、中文逗号或空格分隔，要和 ID 或图号完全一致
@001 备注内容给 001 加一条内部备注
@001 #urgent / @001 -#urgent加标签备注 / 去掉这个标签
@001 due:2026-02-15 或 dl:02-15改截止日；只写月日（02-15 或 02.15）就是今年
@001 to:张三,李四把审图人换成这几个人；add: 追加，rm: 去掉，不分大小写
@张三 add: 001 002 / @张三 rm: 001 002反过来写：把这个人加到几张图纸上，或从图纸上去掉；在搜索框里按 Enter 也能用
@001 c:12/3手工设意见总数/未关闭数；有 PCF 的图纸不允许，提示 “The comment count is managed by the PCF and cannot be edited manually.”
@001 v:3改版本；有 PCF 的图纸不允许，提示 “The version is managed by the PCF and cannot be edited manually.”
@001 rd:B一律不允许，轮次只能靠状态流转改变

@ 后面的编号可以写 ID、完整图号，或图号的一部分（包含即可匹配）；批量改状态的 @R/@W/@A 例外，要完全一致。

Send All 一键发送 看代码推断

  1. 把要发的图纸审完

    所有审图人都在 Tracker 勾了完成，图纸进入 Ready Drawings。要直接批准的，先点 APR。

  2. 点 Send All

    弹出确认：“Update the status of N Ready drawing(s): • a → Approved • w → Waiting Reply. After sending, a builder PCF archive for p drawing(s) downloads automatically (x without a PCF will be skipped). Continue?”。只有点了 APR 的转 Approved，其余全部转 Waiting Reply；压缩包里包括这些 Ready 图纸中所有有 PCF 的。

  3. 等它跑完

    按钮依次显示 Sending...、Verifying...、Packing...：先保存状态、清掉这些图纸的勾选和 APR，再从服务器回读核对，最后下载一个压缩包，里面是每张图纸的船厂版 HTML。

  4. 发邮件

    把压缩包发给船厂。压缩包没保存好，点顶部的 Download Again 重新生成。

  • “Statuses were updated locally, but saving to the server failed. Click Save Now to retry.”：状态只改在本地，没存到服务器。点右下角 Unsaved Changes 卡片上的 Save Now 重试（3 秒后也会自动再存）。
  • “Saved, but the server write check failed …”：点 Refresh 核对状态，需要时再点 Save Now。
  • “Statuses were sent, but the archive download failed …”：状态已经改了，点 Download Again 再下一次，或点 Dismiss 关掉提示。
  • 没有 PCF 的图纸：状态照改，但不进压缩包。

Comments 意见总表

把整个项目所有图纸的意见列成一张表，每条意见只显示最新一轮，船东意见取最近一次非空的内容。所有人都能看。

  1. 设筛选

    可选 Discipline（专业）、Drawing status（图纸状态）、Comment status（意见状态）、Round、Tag、Open older than (days)（未关闭超过多少天），以及 Search all round text（搜图号、标题、意见编号、标签、所有轮次的意见和回复原文、提出人和回复人）。

  2. 点 Apply filters

    改了筛选不点 Apply 不会生效，页面会提示 “Filters changed — apply to update the register.”。Reset 清空。

  3. 看表、排序

    列为 Drawing、Discipline、Dwg Status、No、Round、Status、Tags、Issued by、Owner comment、Builder reply、Updated。点列头排序，默认按更新时间倒序；有附图的显示图片图标；每页 25、50 或 100 条。

  4. 点一行跳到那条意见

    在新标签页打开那张图纸的 PCF，自动滚到这条意见并高亮；用键盘选中行后按 Enter 也行。

  5. Export Excel

    导出所有符合筛选的行，不只是当前页。筛选改了没 Apply 时按钮是灰的。文件里有 Comments 和 Statistics 两个工作表；超长的文字会拆成几行（Part / Parts 列标出是第几段）。

  • 数据不会自己变：别人改了意见，顶部会出现 “Project changes detected. The register is unchanged until you refresh.”，点 Refresh register 才更新。
  • 顶部的 N drawing warnings：表示有几张图纸的 PCF 读不到，展开能看到是哪几张。

Activity 进度报告

生成可以打印的 A4 报告，所有人都能看。

  • 时间范围：7D、14D、30D、60D，或 Custom 自选两个日期（点 ✕ 取消）。日期只影响图纸动态，意见部分始终是全项目的最新快照。
  • 报告内容：项目概况和船舶里程碑（来自 Config 的 Project Summary）、当前状态分布、各专业状态、状态趋势、每日/每周动态、最活跃专业、状态流转统计。
  • 意见页：意见总数、未关闭、已关闭、未关闭超过 30 天、有未关闭意见的图纸数；各专业关闭情况、未关闭意见的天数分布；未关闭最多的前 10 张图纸和最久的 6 条未关闭意见。点柱子或意见弹出明细。
  • 打印：点 Print / Export 用浏览器打印，可另存为 PDF。意见快照没载入、数据已变（提示 “Refresh the comments snapshot before issuing this report.”）或日期无效时不能打印，先点 Refresh comments。

船厂回复导回记录（Builder Reply）

批量导回（主表 Import Builder Replies）和单个文件导回（在线 PCF 的 EXPORT ▾ → Import Builder Reply）每成功合并一个文件，服务器就记一条 Builder Reply 日志。船厂回复不改意见总数和未关闭数，所以以前在 Log 里看不出来，现在切到 Server 就能看到，例如：

  • Builder replies imported: 2 replies (Round B) · status unchanged (Reviewing)
  • Builder replies imported: 1 reply (Round A) · status Waiting Reply -> Reviewing
  • 内容：导回的回复条数、回复的是哪一轮、状态结果；Note 列写来源（Builder reply import (bulk) 或 Builder reply import (PCF)）。
  • 状态规则不变：导回只会把 Waiting Reply 转回 Reviewing（这一步另有一条 Status 记录），其他状态一律不动；Export to Builder 不改状态。
  • 不会重复记：同一批次重放、重复导回同一份文件（Duplicate import）或文件里没有新回复，都不会多记一条。
  • 导出：Copy、CSV 都包含这些行；Export PDF 在发文记录下方单列一节 “Builder Replies Imported”（需要先切到 Server）。筛选里点 Builder reply 只看这类记录。

Local Backup 和 Local Restore Restore 看代码推断

  • Local Backup：下载 PA_项目名_年月日时分.json，包含项目数据和 Tracker 数据。不包含项目密码、密码哈希、PCF 意见内容和图片；任何 API 与后台导出也不会返回项目密码或哈希。整库备份要在服务器上做（见部署运维）。

图纸控制区

  • 默认锁着：点小锁解锁，才能改 Project、图名、图号、版本、文件夹号和审批状态。轮次日期随时可以选。
  • 审批状态：Not submitted、Under review、Approved、Approved with comments、Rejected。自动规则：加了第一条未关闭意见，Not submitted 自动变 Under review；所有意见从有未关闭变成全部关闭，自动变 Approved；空图纸不会自动批准。手动改的状态会保留到下一次全部关闭为止。
  • 意见统计：Total、Open、Closed 和当前轮次字母，会自动同步到主表的意见数。
  • PCF history 表：每轮的版本、船东意见日期、船厂回复日期。每轮日期登记一次。Register round（登记新轮次）要先解锁。
  • Full history：弹窗看全部轮次、登记和流转审计、审批状态变化。

写意见

  1. 加一条意见

    点 + Add comment，或在输入框外按 N。每条意见有固定 ID，显示的编号在删除后会重排。

  2. 填内容

    每轮一行，左边船东意见、右边船厂回复。姓名在意见标题里改，新轮次会沿用上次填的名字。

  3. 打属性标签

    卡片上的 SPEC、highlight、site verify、Cost Affect 点一下开关，工具栏可以按这些属性筛选。

  4. 关闭或重开

    把状态胶囊左右拖动切换 Open/Closed，单击没有反应；键盘用左右方向键。关闭的意见是只读的，要改先重开。

  5. 开新一轮

    单条意见点卡片上的 + Round；工具栏的 + Round to open 给所有未关闭意见一起加一轮，包括其他页的。从船厂导回时平台也会自动开新轮。

  6. 删除

    卡片上的 Delete。只有没有回复文字和回复图片的轮次能单独删；确认后永久删除。

保存

  • 手动：点 SAVE。

HISTORY 和船厂的往来记录

每次 Export to Builder 都会在这里留一行：导出时间、轮次、基线版本（Base rev）、状态（如 Awaiting reply），以及 Download（重新下载当时发出的文件）和 Void。每次导出都有自己的基线，导回时按这个基线合并。

  • Void 作废导出（管理员，访客看到的按钮是灰的）：发错文件或想让某份文件失效时用。作废后这份文件的回复不能再导回，但仍然可以下载。
  • 服务器历史快照 看代码推断：每次保存服务器都留快照，按规则保留：最近 50 份全留，30 天内每天留最后一份，30–180 天每周一份，更早的每月一份。页面上没有入口，只能通过接口查看（GET /pcf/项目/图纸/history）和恢复（POST /pcf/项目/图纸/history/序号/restore）。

保存冲突弹窗 看代码推断

两个人同时改了同一份 PCF 的同一处，后保存的人会看到冲突弹窗。每处冲突选 Use Mine（用我的）、Use Server（用服务器的）或 Manual merge（手工合并）。底部按钮：Later（稍后处理）、All Mine、All Server、Load Server version（放弃本地改动、载入服务器版）、Apply decisions and save（按选择保存）。

手机上

菜单收起时不占位置，展开超出屏幕会自动挪回来，页面不会左右溢出。

和船厂往来：导出、离线回复、导回

船东：导出给船厂

  • 批量：Tracker 的 Send All（管理员），改状态并下载压缩包。
  • 单张：在线 PCF 的 EXPORT ▾ → Export to Builder，下载一个 HTML。单张导出不会改主表状态，要转 Waiting Reply 请管理员在主表改。
  • 发送：把文件作为邮件附件发给船厂，文件是自包含的，图片都在里面。

船厂：离线填写回复

  1. 打开文件

    把邮件里的 HTML 保存到电脑，双击用浏览器打开，推荐 Chrome 或 Edge。顶部是黄色提示条：“Builder reply file — Please fill in the Builder replies, save this HTML file and return it by email. Owner comments and drawing control are read-only.”

  2. 填回复

    只有本轮、未关闭意见的 Builder 一栏能写，可以贴图。船东意见、图纸控制区、轮次登记都是只读的；关闭的意见会提示 “Reopen this comment before editing.”。

  3. 另存

    点黄色提示条旁边的绿色按钮 Save copy to return（和 Save options → Save as 一样）。Chrome 和 Edge 会弹出保存对话框，其他浏览器直接下载。

  4. 发回

    把另存的 HTML（多张可以打成 ZIP）邮件发回船东。不要用别的工具改文件内容，文件名可以改，匹配靠的是文件里的编号。

船东：批量导回 Import Builder Replies（管理员）

  1. 打开导回窗口

    主表点 Import Builder Replies（手机在 More 里），或直接把文件拖到主表上。

  2. 放入文件

    拖入或选择 ZIP 或多个 .html。一次最多 50 个文件、共 50 MB。

  3. 点 Preview replies

    逐个文件列出 File、Drawing、Round、New replies、Auto、Conflicts、Result、PAPC status。匹配靠的是文件里嵌的导出编号，不看文件名。

  4. 点 Apply all clean

    导回所有没有冲突的文件。写入前会再预览一次，这期间有人改了的会变成 Conflict。图纸是 Waiting Reply 的自动转回 Reviewing 并进入下一轮；其他状态不动；不会自动变 Approved。每个导回成功的文件在 Log 里记一条 Builder Reply。

  5. 处理冲突

    Conflict 行点 Resolve…，会打开那张图纸的 PCF 逐条处理；不想处理点 Skip。没处理的冲突、跳过的、船东内容被改的，下次打开窗口还会列出来。点 New import 重新开始。

预览结果意思怎么办
Ready to apply可以直接合并Apply all clean
Conflict船厂回复和平台上的改动撞在同一处Resolve… 或 Skip
No changes文件里没有新回复不用管
Owner changed船厂改了只读的船东内容，但也有新回复导回回复，船东内容的改动被忽略
Unable to match本项目里找不到对应的导出，或压缩包无效、加了密确认是不是这个项目发出的文件
Duplicate import这份导出已经导回过不用管
Applied / Failed / Skipped已合并 / 失败 / 已跳过失败的看提示后重试

上传的文件会作为凭证保留在服务器 data/pcf/项目/imports/ 下。

船东：单个文件导回（管理员）

  1. 打开那张图纸的在线 PCF

    EXPORT ▾ → Import Builder Reply，选船厂发回的 HTML。

  2. 看预览

    分三块：Automatic merges（自动合并）、Conflicts（冲突）、Ignored changes（被忽略的改动，比如船厂改了只读内容，会写明位置和原因）。

  3. 处理冲突

    每处选 Use Server、Use Builder 或 Manual merge；图片按整组比较（Builder images / Server images）。也可以点 All Builder 或 All Server 一次选完。

  4. 点 Apply

    合并写入，点 Cancel 放弃。状态规则和批量导回一样：只有 Waiting Reply 会转回 Reviewing，其他状态不动；同样在 Log 里记一条 Builder Reply。

提示条和多人编辑冲突

黄色：保存冲突

主表和项目设置保存时只发改过的字段，并带上版本号和改之前的值。

  • 改的是不同字段：比如一个人改标题、另一个改专业，两边都保留，不提示。
  • 改的是同一字段：后保存的人这一批一条都不写入，页面顶部出现黄色提示条，例如 “Save conflict: DW-A-001 (Version) changed by someone else first. Nothing was saved this time. …”。
  • 冲突后的处理：冲突的字段换成服务器上的最新值，你其他没冲突的改动保留，下次自动保存时再发。看一下换回来的值，需要的话重新改。
  • 项目设置冲突：提示写 “Save conflict: project settings (Round A Cycle) changed by someone else first …”；专业负责人按专业分别比较。
  • 旧页面不受保护：平台更新后，还开着旧页面没刷新的人保存时仍会直接覆盖。更新后让大家刷新一下。

红色：项目不存在

  • 打开时服务器上没有这个项目：顶部红色提示 “Project "…" does not exist on the server…”，页面停在项目选择页，不会打开本地那份旧数据。
  • 正开着的项目被别人删了：提示写 “no longer exists”。
  • 例外：刚用 Create Workspace 建好、还没第一次保存到服务器的项目，照常打开。

安装和启动

  1. 装 Node.js 24.x

    服务器用 Node 自带的 SQLite，要 24.x。

  2. 装依赖

    npm ci。仓库里的 .npmrc 指向华为云镜像；要走官方源加 --registry=https://registry.npmjs.org/。

  3. 构建

    npm run hub:build，前端和服务器一起构建。

  4. 启动

    设好环境变量后 npm run hub:start，默认端口 8080。服务器不读 .env，只读进程环境变量。

  5. 更新版本

    拉新代码后重新 npm run hub:build 再重启；推到 main 不会自动部署。

数据目录和备份

  • 里面有什么：数据库 papc.db；每张图纸的 PCF pcf/项目ID/图纸ID.json；历史快照 .history/图纸ID/；按哈希存的图片；船厂回传文件 imports/；导出签名密钥 .pcf-export-key。
  • 怎么备份：停掉 Hub，把整个数据目录拷走，包括 .pcf-export-key。少了这把密钥，已经发给船厂的文件就导不回来。页面上的 Local Backup 和后台的导出整库都不含 PCF 文件，不能代替这一步。

启动时自动迁移

Hub 启动、开始监听之前，会检查有没有旧的 HTML 格式或混合存储的 PCF。有的话：

  • 先备份：把 PCF 目录和数据库备份到 数据目录/backups/before-pcf-json-时间-编号/。
  • 再转换：转成 JSON，原来的 HTML 目录改名保留为 pcf-html-backup-*。
  • 失败时：日志写明原因，继续用旧格式读写；修好原因后重启会再试。
  • 只做一次：成功后不再重复。

自动迁移只管 HTML 转 JSON，不管图片。图片拆分要自己跑下面的 hub:migrate-pcf-images。

项目密码：升级与自动迁移

  1. 停服、备份并配置管理员密码

    升级前停止 Hub，备份整个数据目录。对外部署必须设置 ADMIN_PASSWORD；否则所有访客都按本地开发模式视为管理员，免输项目密码。拉代码后重新 npm run hub:build 再启动，推到 main 不会自动部署。

  2. 启动先备份、再迁移

    监听之前，SQLite VACUUM INTO 创建含已提交 WAL 内容的一致全库备份：PAHUB_DATA_DIR/backups/before-project-password-<时间戳>-<随机编号>.db。随后事务中使用 node:crypto 的 scrypt 和随机盐，把旧明文迁到独立 project_passwords 哈希表，并删除 project_settings.password。迁移幂等，无明文则不再备份，无需手工重设原密码。数据库和备份目录须可写；备份或迁移失败会拒绝启动，不会继续明文服务。

  3. 保护旧明文备份

    迁移备份仍包含旧明文密码，要限制文件权限、离线保管，Windows 上核对 ACL。不要放进仓库或经网页下载。API、项目详情/列表、JSON 和后台导出均不返回密码或哈希。

  4. 需要回滚时

    先停服、另存当前数据库，再将迁移前备份恢复到 PAPC_DB_PATH；移走当前库的 -wal / -shm 文件，并按完整备份恢复相关数据，再启动匹配旧版本。不要让旧版本直接运行在迁移后的库上。重启后需重新建立项目解锁会话。

图片迁移 hub:migrate-pcf-images

  1. 停服并备份

    停掉 Hub，把整个数据目录拷一份。

  2. 试跑

    npm run hub:migrate-pcf-images -- --data-dir <数据目录> --dry-run

    只统计，不写入。

  3. 实跑

    npm run hub:migrate-pcf-images -- --data-dir <数据目录> --hub-stopped

    要改的文件先复制到 data/pcf-image-migration-backup/时间/，核对无误后才替换。可以重跑，第二次转换数为 0。

  4. 启动 Hub

    确认没问题后，备份目录可以删。注意：之后每张图纸下次保存时，会按新的保留规则删掉多余的旧快照。

小技巧和常见问题

小技巧

  • 从意见直接跳进 PCF：Comments 里点一行，打开对应 PCF 并高亮那条意见。
  • 批量改状态：命令栏 @R 001,002,003，比一行行下拉快。
  • 批量换人：@张三 add: 001 002 把一个人加到多张图纸。
  • 催办：Tracker 点 Urge List 只看过期的，再 Export CSV 发给大家。
  • 标记要事：给图纸加 #urgent 或 #hold 备注，主表 ID 前出现红点或琥珀点，搜索 show:#urgent 一下都能找到。
  • 批量导回最省事：把船厂发回的 ZIP 直接拖到主表上。
  • PCF 快捷键：输入框外按 N 加意见；Ctrl+B/I/U 改字形；状态胶囊左右拖开关；双击行的下边恢复行高。
  • PCF 里批量开新轮：+ Round to open 一次给所有未关闭意见加一轮。
  • 意见太多滚不动：PCF 每页设 25 条，用 ☰ Index 跨页跳转。
  • 发错给船厂的文件：在 HISTORY 里 Void 掉，这份的回复就导不回来了。

常见问题

  • 按钮是灰的、提示 “Administrator permission required”：右上角登录管理员。
  • 主表里版本和意见数改不了：有 PCF 的图纸这两项由 PCF 管，到 PCF 里改。
  • 轮次怎么改：不能手工改。Waiting Reply 转回 Reviewing 时自动加一，导回船厂回复时会自动转。
  • Comments 里看不到最新意见：点 Refresh register。
  • Activity 报告打印不了：先点 Refresh comments。
  • 船厂说文件存不了：让他们点绿色的 Save copy to return，用 Chrome 或 Edge；其他浏览器会直接下载到下载文件夹。
  • 导回时显示 Unable to match：文件不是这个项目发出的，或压缩包损坏、加了密。
  • 导回时显示 Owner changed：船厂改了船东意见，这部分会被忽略，回复照常导入。
  • 图纸删错了：删除在下次保存时生效。还没保存时，切换项目并选择放弃改动可以撤回 看代码推断；已经保存就只能从备份恢复。
